# 基于轨迹的点云与 Gaussian 路径图

本方法把一条已有三维轨迹与场景结合，生成白底、局部剖切、路径和方向视锥的静态图。默认使用普通点云，也可以切换到仓库已有的 Gaussian 后端。两种后端共用裁切、相机和标注。

工具不寻找路线、不识别楼梯、不进行自动配准或碰撞验证。输入必须已经处于同一坐标系和单位。轨迹可以是实测或手工示意；默认按示意处理。

## 1. 最小使用流程

准备场景 PLY 和带表头的 CSV：

```csv
x,y,z
0,0,0.1
0,2,0.1
0,2,0.3
0,3,0.3
```

行顺序就是行进顺序。只接受三个名为 `x`、`y`、`z` 的列（可以换列序），至少两个不同位置，数值必须有限。相邻重复位置会删除并计数；非相邻重复点保留，以支持回环和折返。工具不平滑、重新规划或补全轨迹。

```bash
plyscene render data/scene.ply \
  --trajectory data/route.csv \
  --route-config configs/route_default.json \
  --output outputs/route_points.png

# 同样的场景和轨迹，切换渲染后端
plyscene render data/scene.ply \
  --trajectory data/route.csv \
  --route-config configs/route_default.json \
  --backend gaussian --output outputs/route_gaussian.png
```

Gaussian 后端要求输入本身包含有效 Gaussian 属性，并具备 CUDA 环境。普通 XYZRGB 文件不能通过切换后端变成 Gaussian 模型。

`--config` 控制原有渲染参数；`--route-config` 控制裁切和路径标注。轨迹模式在未指定俯视角时采用45°；不使用轨迹时原有默认值不变。现阶段轨迹入口只用于 `render`，不改变 `batch` 清单格式。

先加 `--plan` 检查输入文件头、轨迹内容、配置与输出冲突。预检不创建文件、不读取全部场景、不加载 GPU，也不能证明裁切后仍有场景点或环境能完成渲染。

## 2. 数据与坐标

- PLY 输入约定见 [数据格式](data_format.md)。彩色点云使用 RGB；Gaussian 文件作为点云时使用中心位置与 DC 颜色，不使用 Gaussian 形状或透明度混合。
- CSV 的位置必须直接对应原 PLY 坐标。若原轨迹属于机器人基座、相机或其他坐标系，应在输入前处理外参和世界坐标变换。
- `rotate_x` 同时用于场景和轨迹的展示与裁切计算，形成 Z-up 的展示坐标；它不改变导出的 PLY 或轨迹数值。不要只旋转一方，或对已经旋转的场景重复旋转。
- 单位沿用原文件。半径、高度和视锥尺寸都使用该单位；米制配置不能直接用于毫米场景。
- `floor_offset` 指轨迹相对地面的高度，不是自动给路线增加的高度。如果输入是离地1.2米的相机中心，设置1.2；如果是地面上方0.1米的绘图路线，设置0.1。轨迹仍按输入位置画出。

Gaussian 中心点不一定均匀覆盖表面，因此点云图可能比 Gaussian 图稀疏。增大点径会增加覆盖，也会显得粗糙；模糊不等于恢复缺失几何。本功能不增加合成点、不补墙、不进行点云柔化或景深处理。

## 3. 沿三维轨迹自动生成局部裁切

先做已有的有限数、可选透明度阈值与 `bounds` 筛选，再在全部筛选后点上计算轨迹裁切。预览抽样发生在裁切之后。

对每条轨迹线段 `[a,b]`，在展示坐标 XY 平面求点 `q` 的最近位置：

```text
u = clamp(dot(q.xy-a.xy, b.xy-a.xy) / ||b.xy-a.xy||², 0, 1)
r = a + u(b-a)
水平距离 = ||q.xy-r.xy||
局部地面高度 = r.z - floor_offset
```

水平距离不超过 `radius` 的点成为候选；高度下界是局部地面减去 `below`，上界由相机侧别确定。垂直线段没有 XY 长度，使用固定 XY 与整段起终高度范围，避免除零并保留立面上的上升段。

最终取所有线段保留区域的并集。局部地面随轨迹高度变化，因此台阶、坡道和多层路径不需要统一铺到一个水平面。相比全局 XYZ 包围盒，它不会把所有中间高度都无条件保留。对相同 XY 上的上下层路线，两个局部高度带可能同时存在或相互重叠，这是并集规则的结果。

实现按场景点分块计算，先用轨迹总包围盒缩小候选范围；仅合并同向共线的轨迹采样用于裁切加速，原轨迹及弯折、回头均保留。复杂度仍近似为候选点数乘有效线段数，长而曲折的高频日志可能耗时较长。

## 4. 自动降低近侧遮挡

相机方位角在展示 XY 平面的方向记为 `v=(cos(azimuth), sin(azimuth))`。对上述最近点 `r`，计算：

```text
near = dot(q.xy-r.xy, v) > near_distance
高度上界 = 局部地面 + (near_height if near else far_height)
```

这使观察者一侧的墙、柱上部更容易被切掉，远侧立面保留较高高度。它只是基于位置的剖切规则，**不识别哪些点属于墙或柱，也不是逐像素可见性优化**。相同区域的家具也可能被切掉；回环、多层重叠、宽走廊或大尺度 Gaussian 仍可能产生遮挡。

调整次序建议为：先核对坐标和 `floor_offset`，再确定 `radius`，然后选择 `azimuth`，最后调 `near_height`、`far_height` 和 `near_distance`。不通过自动删除任意“看起来碍事”的物体来保证路径畅通；保留原文件，并在报告中记录裁切参数。

路径与视锥作为二维图解覆盖，不参与场景深度遮挡，因此不会被墙面完全盖住，但可能视觉上覆盖墙面。这不代表那里可通行。

## 5. 相机、点径与阴影

复用仓库的**正交相机**。点云和 Gaussian 使用同一相机矩阵与内参。场景裁切结果、完整轨迹和视锥角点共同参与取景，避免标注因只按场景范围取景而被截断。

渲染 JSON 常用参数：

| 参数 | 含义 |
|---|---|
| `azimuth` | 水平方位角，决定近侧裁切与画面左右关系 |
| `elevation` | 俯视角，轨迹模式缺省45° |
| `rotate_x` | 原数据转为展示 Z-up 的旋转 |
| `framing` | 主体占投影范围的比例，缺省0.78；调小相当于拉远，范围 `(0,0.90]` |
| `point_radius` | 普通点的最终像素半径，整数；不影响 Gaussian |
| `width/height/ssaa` | 最终尺寸与超采样倍率 |
| `shadow` | 合成足迹阴影强度，缺省0；不是物理光照 |

内部先按超采样分辨率渲染与绘制标注，再缩小。只对阴影做模糊，场景不做额外柔化或远景虚化。阴影把点投到最低地面下方的平面，因此多层结构的阴影仅用于展示，不表达真实层间光照。

旧实验脚本使用过透视投影、双层阴影、手工删除门柱和不同去噪策略。通用实现使用已有正交相机与共用阴影、自动近侧裁切，**不是这些旧图片的逐像素复刻**。

## 6. 路径与三维切线视锥

视锥按三维弧长等距布置。每个尖端通过线段内插值获得，严格位于轨迹折线上，不额外增加 Z 偏移。方向取该处线段的三维单位切线，包含上楼、下楼和竖直运动，不把 Z 分量清零。

以切线为前向构造正交左右、上下轴。切线接近竖直时更换参考轴，避免叉积为零；在折角处采用前进方向的线段方向，不做姿态平滑。随后用统一相机投影尖端和四个底面角点，绘制线框。

**这些视锥始终是路径切线方向示意，不是真实相机姿态，也不代表标定的视场角。** `kind=recorded` 只表示用户声明轨迹来源为记录，不会把视锥变成实测姿态。

路径配置完整模板见 [route_default.json](../configs/route_default.json)：

| 参数 | 缺省值 | 单位/说明 |
|---|---:|---|
| `radius` | 1.65 | 沿线水平半径，场景单位 |
| `floor_offset` | 0.10 | 轨迹离地高度，场景单位 |
| `below` | 0.25 | 局部地面以下保留量 |
| `near_height` / `far_height` | 0.60 / 1.70 | 近侧/远侧保留高度 |
| `near_distance` | 0.15 | 判定近侧的水平偏移阈值 |
| `line_width` | 9 | 路径最终像素宽度 |
| `frustum_count` | 12 | 等弧长视锥数量；0关闭视锥 |
| `frustum_length` | 0.30 | 尖端至底面中心的距离 |
| `frustum_width` / `frustum_height` | 0.225 / 0.18 | 底面完整宽高，不是半宽半高 |
| `frustum_line_width` | 3 | 视锥最终像素线宽 |
| `route_color` / `frustum_color` | 红/青 | RGB颜色字符串 |
| `start_color` / `end_color` | 青绿/粉 | 起终点颜色 |
| `kind` | `illustrative` | `illustrative` 或用户声明的 `recorded` |

## 7. 输出与可追溯性

以 `--output outputs/example.png` 为例，生成：

- `example.png`：最终图，底部区分示意/记录轨迹并注明切线视锥。
- `example.crop.ply`：全部裁切幸存点，保持原属性、类型、顺序和坐标。Gaussian 属性不会丢失。即使使用预览抽样，裁切文件仍是全量幸存点。
- `example.trajectory.csv`：仅删除相邻重复位置后的轨迹，保留来源坐标。
- `example.json`：输入与输出指纹、轨迹来源、配置、各阶段数量、矩阵、视锥尖端、裁切索引摘要、依赖与 Git 状态等。

任意目标文件已存在则拒绝覆盖，包括预检。执行失败可能留下已写出的部分成果；检查错误后使用新的输出名或自行清理确认无用的部分文件。

比较双后端时，固定同一场景、轨迹、渲染配置和路径配置，使用不同输出名。核对报告中的 `trajectory.selected_indices_sha256`、相机矩阵与内参。不要将不同采样数、取景或清理版本的差异都归因于渲染后端。

## 8. 验收与限制

先确认路线的单位和坐标，再看图检查：起终点均在画面内；上升段与台阶高度关系合理；尖端无偏离；近侧剖切有效且保留远侧结构；缩到论文展示尺寸后红线和视锥可辨。

自动裁切不保证建筑语义完整、场景覆盖完整或无障碍通行；源数据孔洞、漂浮噪点、大尺度 Gaussian 边缘拖影不会自动消失。已有 `denoise` 命令可用于另外保存清理副本，但不要把丢失的真实结构当成渲染故障。

可复现案例见 [瀛洲园示例](../examples/yingzhouyuan/README.md)。几何与文件契约测试运行：

```bash
python -m unittest discover -s tests -v
```

测试覆盖 CSV 和参数校验、近侧随相机改变、台阶与多层高度并集、竖直切线、显示旋转一致性、尖端在线、属性保留、裁切后抽样及拒绝覆盖。GPU 实际渲染还需在具备依赖的环境中单独验证。
